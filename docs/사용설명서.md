## 1. 프로그램 받기

1. GitHub 저장소 → 위쪽 **Actions** 탭
2. 목록에서 `Windows 실행파일 빌드` 중 최근 것(초록 체크 표시) 클릭
3. 페이지 맨 아래 **Artifacts** → `연금계리산출-windows` 클릭해 내려받기
4. 압축(`연금계리산출.zip`)을 풀면 이렇게 들어 있습니다

```
연금계리산출.exe              더블클릭하면 창이 뜹니다. 보통 이것만 쓰면 됩니다
pension-cli.exe               명령프롬프트에서 배치로 돌릴 때
기본자료\
    명부_기본.xlsx            기본 명부 — 재직 290명·퇴직 28명 (실제 평가 사례)
    기초율_기본값.xlsx        표준 퇴직률·승급률·사망률이 채워진 기초율
    명부_양식.xlsx            빈 명부 양식 (작성 예시 두 줄)
    기초율_빈양식.xlsx        처음부터 회사 값으로 채우고 싶을 때
설명서\
    사용설명서.md             이 문서
    계리방법론.md             산출 근거
    지급률규정-작성법.md      퇴직금 규정을 표·수식으로 옮기는 법
```

> 설치 과정이 없습니다. 원하는 폴더에 두고 바로 실행하십시오.
> 처음 실행할 때 "Windows의 PC 보호" 창이 뜨면 **추가 정보 → 실행** 을 누르십시오.
> 서명되지 않은 실행 파일이라 나오는 안내입니다.

### 먼저 한 번 돌려 보기

`기본자료` 의 두 파일만으로 산출이 끝까지 돕니다. 회사 자료를 넣기 전에
화면이 어떻게 흘러가는지 먼저 보십시오.

1. `연금계리산출.exe` 실행
2. 명부에 `기본자료\명부_기본.xlsx`, 기초율에 `기본자료\기초율_기본값.xlsx`
3. **[산출 실행]**

재직 290명·퇴직 28명 규모의 결과 엑셀이 나옵니다. 실제 평가 사례의 명부라
DC 가입자가 섞여 산출대상에서 빠지고, 근속 1년 미만 퇴직자가 지급액 없이 들어오고,
임원의 직군이 '정규직' 으로 적혀 오는 등 **실제 명부에서 마주치는 형태** 가 그대로
들어 있습니다.

> 제도구분 누락 같은 **실제 오류도 그대로** 있습니다. 그래서 이 명부는
> **[검증 오류가 있어도 산출 강행]** 을 켜야 끝까지 돕니다. 검증 리포트가 무엇을
> 잡아내는지 보기에 오히려 좋습니다.

## 2. 준비물 두 가지

### 명부 파일

기존에 쓰던 엑셀 통합문서 그대로 쓰거나, `기본자료\명부_양식.xlsx` 를 복사해
채우십시오. 다음 세 시트가 있어야 합니다.

* `Input` — 산출기준일(C3), 평균임금 체크금액(C5), 직군 규칙(B12부터)
* `재직자명부` — 26행부터 데이터
* `퇴직자명부` — 22행부터 데이터

### 산출 가정 입력

가정은 **화면에서 직접 입력** 하거나, 엑셀 양식을 받아 채우는 두 가지 방법이 있습니다.

#### 방법 A — 입력 화면 (권장)

1. `연금계리산출.exe` 실행
2. **명부 파일** 을 먼저 선택 (직군명을 가져오기 위해)
3. **[산출 가정 입력]** 클릭
4. **직군 매핑** 탭에서 [명부에서 직군 읽어오기] — 명부의 직급·직군을
   산출 묶음으로 배정합니다 ([아래](#직군-매핑) 참고)
5. 탭을 옮겨 가며 값을 넣고 **[저장]**

처음이라면 **[예시 채우기]** 로 흔한 값을 한 벌 깔아 놓고 고치는 편이 빠릅니다.
저장한 파일은 기초율 파일 칸에 자동으로 지정됩니다. 엑셀에서 열어 고친 뒤
**[불러오기]** 로 다시 가져와도 됩니다.

명령행에서 화면만 띄우려면:

```bat
pension-cli assumptions --roster 명부.xlsm
```

검증만 먼저 돌려 보려면 기초율을 **함께** 주십시오. 직군 매핑이 기초율의
`지급규정` 시트에 있으므로, 명부만 주면 calc 와 다른 판정이 나올 수 있습니다.

```bat
pension-cli check 명부.xlsm 기초율.xlsx
```

#### 방법 B — 기본값에서 고치기

`기본자료\기초율_기본값.xlsx` 를 복사해 엑셀에서 고칩니다. 시트마다 빨간
글씨로 **[필수 확인]** 이 적힌 곳이 회사 값으로 바꿔야 하는 자리입니다.

| 시트 | 손봐야 하나 |
|---|---|
| `사망률` | **아니오.** 표준사망률입니다. 남녀를 나눠 씁니다 |
| `할인율` | **예.** 결산일 현재 우량회사채 수익률. 매 결산 달라집니다 |
| `임금상승률` | **예.** 회사의 임금협상 이력·중장기 계획 |
| `승급률` · `퇴직률` | 표준률입니다. **회사 경험률이 있으면 그쪽이 우선입니다** |
| `지급률` | 법정 퇴직금(1년당 30일분)이면 그대로. 누진제·배수제면 바꾸십시오 |

### 직군마다 가정을 켜고 끄기

직군에 따라 쓰지 않는 가정이 있습니다. **지급규정** 탭 오른쪽 네 칸에서
`반영` / `미반영` 을 고르면 됩니다.

| 가정 | 미반영으로 두는 경우 |
|---|---|
| `Base-up` | 임금이 계약으로 고정된 직군 |
| `승급률` | 호봉표가 없는 계약직 |
| `퇴직률` | 임원을 정년까지 근무한다고 보는 경우 |
| `사망률` | 사망을 별도로 보지 않는 경우 |

미반영은 그 가정의 요율을 0 으로 두는 것과 같습니다. 기초율 표를 직군마다 0 으로
채워도 결과는 같지만, 그러면 **'값이 0 인 것' 과 '적용하지 않기로 한 것' 을
나중에 구별할 수 없습니다.** 근거자료로 남으려면 의도가 드러나야 합니다.

> **퇴직률을 끄면 채무가 줄어듭니다.** 퇴직금은 중도퇴직해도 그때 지급되므로,
> 퇴직률이 있으면 일부가 이른 시점에 빠져나가 할인을 덜 받습니다. 끄면 전원이
> 정년까지 남아 더 오래 할인됩니다.

퇴직률·승급률·사망률은 연령 15~70세까지 있습니다. **70세를 넘는 연령은 70세 값을
씁니다** — 표는 계단식으로 읽히므로 마지막 행이 그 이후 전 구간에 적용됩니다.

### 시스템 등록 — 금리표·표준률을 한 번만 넣어 두기

한 결산기에 여러 단체를 산출할 때 **금리표는 모두 같습니다.** 결산일이 같으면
우량회사채 수익률도 같기 때문입니다. 표준률도 단체마다 다시 만들 이유가 없습니다.

단체마다 파일을 다시 찾아 지정하면, 스무 단체를 산출할 때 같은 금리표를 스무 번
고르는 셈입니다. 그중 한 번이라도 다른 파일을 집으면 그 단체만 할인율이 달라지고,
**눈에 띄지도 않습니다.**

산출 가정 화면 맨 위 **시스템 등록 자료** 줄에서 한 번 등록해 두면 이후 모든
산출에서 목록으로 골라 쓸 수 있습니다.

| 버튼 | 하는 일 |
|---|---|
| 표준률 [등록] | 표준 기초율 워크북을 등록 |
| 표준률 [불러오기] | 등록된 표준률을 화면으로 가져옴 |
| 금리표 [등록] | KIS-Net 등 만기별 금리표를 등록 |
| 금리표 [적용] | 고른 등급의 현물이자율 곡선을 `할인율` 탭에 채움 |

**불러온 뒤 값을 고쳐도 됩니다.** 등록된 것은 출발점이지 확정이 아닙니다.
표준률을 불러와도 저장 경로는 비워 두므로, [저장] 이 등록 자료를 덮어써서 다른
단체까지 바뀌는 일은 없습니다.

명령행에서도 됩니다.

```bat
pension-cli library add 금리표 KIS금리_20251231.xlsx --name KIS_20251231
pension-cli library add 표준률 표준률_2025.xlsx
pension-cli library list
```

등록 파일은 `%APPDATA%\연금계리산출` 에 **복사** 됩니다. 원본을 참조만 하면
담당자가 그 파일을 옮겼을 때 이후 산출이 조용히 실패하기 때문입니다.

### 단일할인율 — 수익률곡선기법

금리표를 넣으면 만기별로 다른 이자율(현물이자율)로 할인합니다. 그런데 주석에는
할인율을 **하나만** 적어야 합니다.

임의로 한 만기의 이자율을 고르는 대신, **곡선으로 할인한 채무와 같은 현재가치를
내는 단일 이자율** 을 역산합니다.

```
Σ 급여(t) ÷ (1 + r)^t  =  곡선으로 할인한 확정급여채무
```

K-IFRS 1019 문단 85 의 "급여지급의 예상 시기와 금액을 반영하는 단일 가중평균
할인율" 이 이것입니다. 결과 엑셀 `산출요약` 에 이 값이 **적용 할인율(단일할인율)**
로 나오고, 참고로 듀레이션 시점 현물이자율도 함께 적힙니다.

> 두 값은 꽤 다를 수 있습니다. 실제 사례에서 듀레이션(5.9년) 시점 이자율은
> 3.688% 였지만 단일할인율은 4.233% 였습니다. 곡선이 우상향일수록 벌어집니다.
> **이자원가도 단일할인율로 계산합니다.**

### 등급 선택

등급을 지정하지 않으면 AA0 → AA+ → AA- 순으로 찾습니다. 무엇을 우량회사채로
볼지는 회계정책이므로 회사가 정합니다.

빈 양식부터 시작하려면 `기초율_빈양식.xlsx` 를 쓰거나 화면의
**[기초율 양식 새로 만들기]** 를 누르십시오.

#### 탭·시트별로 채울 내용

| 탭 / 시트 | 무엇을 넣나 |
|---|---|
| `직군 매핑` | 명부의 직급·직군을 어느 묶음으로 볼지 |
| `할인율` | 결산일 현재 우량회사채 수익률. 한 줄이면 전 기간 단일 |
| `Base-up` (`임금상승률`) | 승진·승급을 뺀 공통 인상률. 연차별로 다르면 여러 줄 |
| `승급률` | 호봉·승진에 따른 인상률. 조회 기준을 연령/근속 중 고를 수 있습니다 |
| `퇴직률` | 연간 중도퇴직률. 과거 3~5년 경험률 권장 |
| `사망률` | 경험생명표 등의 `qx` |
| `지급률` | 월평균임금 대비 배수. **법정 퇴직금만 쓴다면 비워 두십시오** |
| `지급률 규정` | 규정별 계산 방식(누적/누진/수식) |
| `장기급여` | 근속 포상 지급일수. 없으면 비워 두십시오 |

> **누진제 퇴직금이라면 `지급률 규정` 탭에서 방식을 `누진` 으로 바꾸십시오.**
> 표에 구간별 연 배수만 적으면 됩니다. 자세한 내용은
> [지급률규정-작성법.md](지급률규정-작성법.md) 를 보십시오.

> **열 이름이 중요합니다.** `Input` 시트의 규정명 칸(G~N열)이나 명부의 규정 칼럼에
> 적은 이름과 기초율 시트의 열 머리글이 **글자 하나까지 같아야** 합니다.
> 다르면 해당 인원의 산출 결과에 "규정을 찾을 수 없음" 이 표시됩니다.

> **표는 계단식으로 읽습니다.** 퇴직률 시트에 20·35·50세 행만 있으면
> 27세인 사람은 20세 행 값을 씁니다. 모든 연령을 다 적을 필요는 없습니다.

### 직군 매핑

명부의 `직군` 열에 무엇이 들어올지는 회사가 정합니다. 실제로 받아 본 파일만 해도
이렇게 갈렸습니다.

| 명부 직군 | 임직원구분 | 뜻 |
|---|---|---|
| `정규직` / `계약직` | `직원` / `임원` | 고용형태가 그대로 들어옴 |
| `사원` / `과장` / `대표이사` | `정규사원` / `촉탁사원` / `임원(별정)` | **직급** 이 들어옴 |
| `정규직` | `Senior` / `Master` / `T직` | 임직원구분 칸에 **직급** 이 들어옴 |

기초율(퇴직률·승급률·지급률)은 이 낱낱의 직급마다 만들지 않습니다. 비슷한 것끼리
묶고 그 단위로 세웁니다. 기본 묶음은 **정규직 / 계약직 / 임원** 입니다.

**묶음 이름은 바꿀 수 있습니다.** 생산직과 관리직의 퇴직률이 확연히 다른 회사라면
위쪽 `직군별 규정` 칸에 이렇게 적으십시오.

```
생산직, 관리직, 일반직, 계약직, 임원
```

적용을 누르면 모든 가정 표의 열이 그 이름으로 다시 만들어지고, 매핑 표의 배정
칸에서도 그 이름을 고를 수 있게 됩니다. [기본값] 은 정규직/계약직/임원으로
되돌립니다.

**배정은 제안만 하고 확정하지 않습니다.** [제안대로 채우기] 는 `촉탁`·`기간제`·
`파견` 같은 말이 들어가면 계약직, `이사`·`대표`·`전무` 면 임원으로 찍어 줄 뿐입니다.
같은 '촉탁사원' 이라도 정년 후 재고용이면 계약직, 임원 예우 재고용이면 임원인
회사가 있으므로 **반드시 규정을 보고 확인하십시오.**

> **묶음을 잘게 나눌수록 좋은 것이 아닙니다.** 구간별 인원이 줄면 경험률의 통계적
> 신뢰도가 떨어집니다. 퇴직률·승급률·지급률이 **실제로 다른** 단위로만 나누십시오.

배정 결과는 저장 시 기초율 파일의 `지급규정` 시트에 `명부직군` · `임직원구분` ·
`변환직군명` 세 열로 적힙니다. **산출할 때 이 시트가 있으면 명부의 `Input` 시트보다
우선합니다.** `Input` 은 회사가 채워 보내는 칸이라 비어 있거나 직군만 적혀 오는
일이 잦고, `지급규정` 은 계리 담당자가 규정을 보고 확정한 것이기 때문입니다.

조회는 좁은 것부터 순서대로 맞춰 봅니다.

1. 직군 + 임직원구분 원문 (`과장` + `촉탁사원`)
2. 직군 + 정규화된 임직원구분 (`과장` + `직원`)
3. 임직원구분만 → 4. 직군만

그래서 `과장/정규사원` 과 `과장/촉탁사원` 을 서로 다른 묶음에 넣을 수 있습니다.
임직원구분을 정규화하면 `임원`/`직원` 둘뿐이라 이 구분이 사라지기 때문에 원문을
먼저 봅니다.

## 아이패드에서 쓰기

두 가지 방법이 있습니다. 어느 쪽이든 App Store·개발자 계정은 필요 없습니다.

### 방법 1 — 홈 화면에 설치하는 앱 (권장)

압축파일의 `아이패드웹앱` 폴더를 사내 정적 웹서버(HTTPS)에 올리고,
아이패드 Safari 로 그 주소를 연 뒤 **공유 버튼 → 홈 화면에 추가** 를 누르십시오.

* 앱 아이콘이 생기고 전체화면 앱으로 열립니다
* **모든 계산이 아이패드 안에서** 이루어집니다 — 명부가 기기 밖으로 나가지 않습니다
* 한 번 연 뒤에는 **오프라인에서도** 동작합니다 (전부 캐시됨, 약 14MB)
* 외부 CDN 을 쓰지 않으므로 인터넷이 막힌 사내망에서도 됩니다

같은 산출 엔진이 WebAssembly 로 브라우저 안에서 돕니다. 실제 명부(재직 290명)로
PC 산출과 결과가 원 단위까지 같은 것을 확인했습니다.

웹앱에도 PC 프로그램의 화면이 그대로 있습니다.

* **산출가정 입력 탭** — 직군 매핑 · 할인율 · Base-up · 승급률 · 퇴직률 ·
  사망률 · 지급률 · 지급규정(직군별 반영/미반영 포함) · 지급률 규정(수식
  검증·미리보기) · 장기급여 유형. 저장하면 PC 와 같은 서식의
  `산출가정.xlsx` 가 내려오고, 산출 탭에 바로 연결됩니다. 입력 중이던
  내용은 브라우저에 임시 저장되어 앱을 닫아도 남습니다.
* **기본가정 관리 탭** — KIS-Net 금리표와 표준률 워크북을 등록해 두면
  이 기기의 브라우저 안(IndexedDB)에 저장되어, 다른 단체를 산출할 때도
  목록에서 골라 쓸 수 있습니다. 따로 지정하지 않으면 최근 등록분이
  기본으로 잡히고, 등록이 없어도 내장 표준률(15~70세)은 항상 쓸 수 있습니다.
* **산출 내역 탭** — 산출을 마친 뒤 "2412 1번단체" 처럼 이름을 붙여 저장하면
  명부·산출가정·결과가 통째로 기기에 남습니다. 다음 결산 때 [입력 불러오기]
  로 전기 입력을 그대로 끌어와 재산출하거나, 저장된 결과 요약·엑셀을 다시
  볼 수 있습니다. 같은 이름으로 저장하면 덮어씁니다.
* **전기 산출 연결** — 산출 탭 4번 칸에서 저장된 산출을 고르면 전기말
  확정급여채무·할인율·근무원가가 그대로 채워지고, **전기 기초율까지 함께
  넘어가** 증감분석이 경험조정과 가정변경효과를 나눠 계산합니다. 손으로
  옮겨 적다 자릿수를 틀릴 일이 없습니다.
* **저장된 명부** — 올렸던 명부를 목록에 두고 다음 결산에 그대로 꺼내
  씁니다. 산출 탭에서 [이 파일을 목록에 저장] 을 누르거나 기본가정 관리
  탭에서 등록하면 됩니다. `.xls` 로 받은 명부는 서식 그대로 보관됩니다.
* **가정세트** — 지금 화면의 산출가정 전체(지급률·지급규정·직군 매핑까지)를
  이름 붙여 저장합니다. 같은 회사를 매년 산출하거나 규정이 같은 계열사를
  여럿 맡을 때 [불러오기] 한 번으로 끝납니다. 산출가정 입력 탭의
  [현재 가정 저장] 또는 기본가정 관리 탭에서 관리합니다.
* **산출기준일 · 산출 시작일** — 산출 탭 3번 칸에서 넣습니다. 기준일을
  넣으면 **명부를 고치지 않고** 그 날짜로 산출합니다(가결산·시산). 시작일
  (직전 결산일)을 넣으면 증감분석의 이자원가를 그 기간으로 환산합니다 —
  결산기가 바뀌어 기간이 1년이 아닌 회차에서 이자원가가 부풀지 않습니다.
* **시험명부 탭** — 난수로 만든 시험용 명부 세 벌(재직 290명 안팎)을
  그 자리에서 만듭니다. 표준 / 복합제도(DC·중간정산·임금피크·정년초과
  재고용·전입) / 자료불량(검증 리포트 확인용) 세 가지이고, 명부마다 짝이
  되는 기초율과 **특이사항 안내문**이 함께 나옵니다. 씨앗이 같으면 언제
  만들어도 같은 명부라 산출 결과를 비교할 수 있습니다. PC 에서는
  `pension samples 기본자료 --cases` 로 같은 것을 만듭니다.

#### 기본으로 들어 있는 가정

빈 화면에서 시작해도 말이 되는 산출이 나오도록 두 가지를 미리 넣어 두었습니다.

* **Base-up 전 기간 2%** — 마지막 줄의 값이 이후 전 구간에 적용되므로
  한 줄(1년차 2%)이 곧 전 기간 2%입니다. 회사의 임금협상 이력이 있으면
  그쪽이 우선입니다.
* **지급률은 법정** — 지급률 규정의 기본 방식이 `법정` 입니다. 지급률 표를
  비워 두면 법정 퇴직금(30일 평균임금 × 근속연수)이 적용되고, **표에 값을
  넣으면 그 값이 그대로 쓰입니다.** 누진제·수식 규정일 때만 방식을 바꾸면
  됩니다.

#### 보관함 — 기기 밖에 저장

앱 안의 자료는 브라우저 저장소에 있어 **Safari 방문기록·웹사이트 데이터를
지우거나 기기를 바꾸면 함께 사라집니다.** 그래서 등록 자료(금리표·표준률·명부)와
산출 내역 전부를 파일 하나로 내보낼 수 있게 했습니다.

산출 내역 탭 아래 [보관함 내보내기] → `연금계리보관함_YYYYMMDD.zip` 이
내려옵니다 → 공유 → **파일에 저장 → iCloud Drive**. 되살릴 때는 그 파일을 골라
[가져오기(합치기)] 또는 [전체 교체] 를 누르면 됩니다. 다른 아이패드·PC 에서도
같은 파일로 그대로 복원되므로, 결산이 끝날 때마다 한 번씩 내보내 두십시오.

> 홈 화면 설치와 오프라인 캐시는 HTTPS 주소에서만 동작합니다(브라우저 규약).
> HTTP 로만 열 수 있는 환경이면 Safari 즐겨찾기로 쓰시면 됩니다 — 계산은
> 똑같이 기기 안에서 됩니다.

### 방법 2 — 사무실 PC 를 서버로

PC 에서 한 줄을 실행하고, 아이패드 Safari 로 화면에 표시되는 주소에 접속합니다.

```bat
pension-cli web --host 0.0.0.0
```

* 계산은 PC 에서, 아이패드는 화면 역할만 합니다
* 명부는 산출 즉시 지워지고 서버 PC 에 파일로 남지 않습니다
* **인증이 없으므로 사내 네트워크 밖(인터넷)으로 열지 마십시오**

### App Store 앱은?

기술적으로 가능하지만 권하지 않습니다. 엔진을 스위프트로 다시 쓰거나 무겁게
감싸야 하고, 애플 개발자 계정(연 $99)과 심사가 필요합니다. 위 두 방법이 같은
결과를 더 적은 비용으로 냅니다.

## 4. 오류가 났을 때

### "명부 검증에서 오류 N건이 발견되어 산출을 중단했습니다"

명부에 고쳐야 할 곳이 있습니다. 로그에 이렇게 나옵니다.

```
[ERROR] JAE_WAGE_BELOW_CHECK (재직자명부!K28) 사번=A003: 30일 평균임금 100원이 체크금액 1,000,000원 미만입니다
```

읽는 법: `재직자명부` 시트의 **K열 28행** 을 보라는 뜻입니다. 엑셀에서 그 칸으로
바로 가면 됩니다.

**오류를 모두 한 번에 보여 주므로**, 로그에 나온 곳을 전부 고친 뒤 한 번만 다시
돌리면 됩니다.

### 자주 나오는 오류

| 코드 | 뜻 | 조치 |
|---|---|---|
| `JAE_JOB_GROUP_UNKNOWN` | 명부의 직군에 맞는 규칙이 없음 | **직군 매핑** 탭에서 [명부에서 직군 읽어오기] 를 다시 누르십시오. 명부가 바뀌어 새 직급이 생기면 배정되지 않은 채 남습니다 |
| `JAE_DUP_ID` | 사번 중복 | 메시지에 중복된 행 번호가 모두 나옵니다 |
| `JAE_BIRTH_DATE` | 생년월일을 해석 못 함 | `YYYY-MM-DD` 로 고치십시오 |
| `JAE_WAGE_BELOW_CHECK` | 평균임금이 체크금액 미만 | 임금을 확인하거나 `Input` C5의 체크금액을 조정 |
| `JAE_PLAN_MISSING` | 제도구분 공란 | `DB` / `DC` / `퇴직금제도` 중 하나 |
| `JAE_HIRE_AFTER_BASE` | 입사일이 산출기준일보다 늦음 | 기준일 이후 입사자는 명부에서 빼십시오 |
| `TOI_REASON_MISSING` | 퇴직사유 미입력 | 1~6 중 하나 (1:중도 2:사망 3:DC전환 4:정년 5:전출 6:사업처분) |
| `TOI_FUND_OVER_TOTAL` | 사외자산 지급액 > 총지급액 | 금액을 확인하십시오 |

### 검토용으로 일단 돌려보고 싶다면

**[검증 오류가 있어도 산출 강행]** 을 켜십시오. 다만 그 결과는 **검토용입니다.**
확정 공시 전에는 반드시 명부를 고치고 다시 돌리십시오.

### 경고(WARNING)는 무엇인가

산출은 되지만 담당자가 확인해야 하는 항목입니다. 자동으로 판단할 수 없어서
알려 드리는 것입니다.

* `JAE_NRA_NOT_FUTURE` — 정년을 이미 넘긴 사람. `Input` F열의 가산 연수를 확인
* `TOI_REASON_AMBIGUOUS` — 임금피크 중간정산의 분류가 종전 규칙와 시트 수식에서 갈림
* `XREF_ID_IN_BOTH` — 같은 사번이 재직·퇴직 양쪽에 있음 (DC 전환자면 정상)

## 5. 결과 엑셀 읽기

| 시트 | 쓸 곳 |
|---|---|
| `산출요약` | 재무제표 주석의 기본 수치. 인원·DBO·근무원가·이자원가·듀레이션 |
| `증감분석` | 주석의 확정급여채무 변동 내역 표 |
| `민감도분석` | 주석의 민감도 공시 |
| `기대현금흐름` | 연도별 기대 급여지급액·현가계수. **단일할인율·듀레이션의 검산 근거** |
| `적용가정` | 산출에 실제 쓴 가정 전체의 사본. 결과 파일 혼자서 근거자료가 되도록 |
| `개인별산출` | 검산용. 원가코드별 배분에도 씁니다 |
| `장기급여` | 기타장기종업원급여 (보험수리적손익을 당기손익으로 인식) |
| `검증리포트` | 명부 이슈 전체. 필터가 걸려 있습니다 |
| `UpLoad_Jae` / `UpLoad_Toi` | 기존 종전 규칙가 만들던 업로드 명부와 같은 형식 |

### 결과가 맞는지 빠르게 보는 법

**`산출요약` 의 확정급여채무 ÷ 퇴직급여추계액** 을 계산해 보십시오.
통상 **0.7 ~ 1.1** 입니다. 크게 벗어나면:

* 1보다 많이 크다 → 임금상승률이 할인율보다 지나치게 높지 않은지
* 0.7보다 작다 → 정년연령이 너무 멀지 않은지, 할인율이 과도하지 않은지

**민감도분석의 할인율 ±0.5%p 변동률** 은 대략 `듀레이션 × 0.5%` 여야 합니다.
듀레이션 9년이면 약 4.5%. 크게 다르면 기초율을 다시 보십시오.

### 개인별 결과를 따로 받고 싶을 때

개인별 결과는 산출결과 엑셀 안에 `개인별산출` 시트로 이미 들어갑니다. 원가배분이나
부서 확인용으로 **별도 파일**이 필요하면 두 가지 방법이 있습니다.

* GUI — `2. 산출 옵션` 의 **[개인별 결과 별도 파일로 저장]** 체크
  → 결과 파일 옆에 `<결과파일명>_개인별.xlsx` 로 함께 저장됩니다
* 명령행 — `pension-cli members 명부.xlsm 기초율.xlsx -o 개인별결과.xlsx`

파일에는 시트 세 개가 들어갑니다.

| 시트 | 내용 |
|---|---|
| `개인별산출` | 1인 1행. 퇴직급여와 장기급여를 사번 기준으로 합쳐 놓았습니다 |
| `원가코드별집계` | 명부 `원가코드` 열 기준 집계 — 제조원가/판관비 배분에 씁니다 |
| `직군별집계` | 직군 기준 집계 |

`개인별산출` 시트는 명부를 다시 열지 않아도 되도록 생년월일·입사일·제도구분·
원가코드·적용 규정명까지 함께 담습니다. 머리글에 자동 필터가 걸려 있어 부서별로
걸러 내기 편합니다.

> **회색으로 칠해진 행은 산출에서 빠진 사람입니다**(DC 가입자 등). 행을 지우지 않고
> 남겨 두는 이유는 인원 대사를 위해서입니다. 합계는 이들을 0으로 보고 더합니다.

> **`추계액대비` 열을 확인하십시오.** DBO ÷ 퇴직급여추계액이며 통상 0.7~1.1 입니다.
> 특정 인원만 크게 벗어나면 그 사람의 정년연령이나 지급률 규정을 확인하세요.

## 6. 배치로 돌리기 (선택)

명령프롬프트에서:

```cmd
pension-cli calc 명부.xlsm 기초율.xlsx -o 산출결과.xlsx
pension-cli check 명부.xlsm -o 검증결과.csv
pension-cli template 기초율.xlsx --roster 명부.xlsm

REM 개인별 결과만 별도 엑셀로
pension-cli members 명부.xlsm 기초율.xlsx -o 개인별결과.xlsx
pension-cli upload 명부.xlsm -o 업로드명부.xlsx
```

전기 수치를 넣으려면:

```cmd
pension-cli calc 명부.xlsm 기초율.xlsx -o 결과.xlsx ^
    --prior-dbo 8412530000 --prior-rate 4.8% --prior-assumptions 기초율_전기.xlsx
```

검증 오류가 있으면 종료 코드 `2` 로 끝나므로, 배치 스크립트에서 판정할 수 있습니다.

## 7. 자주 묻는 것

**Q. DC 가입자가 산출에서 빠졌습니다.**
정상입니다. 확정기여제도는 부담금을 납입하면 의무가 끝나므로 확정급여채무가
생기지 않습니다(K-IFRS 1019호 문단 51). `개인별산출` 시트의 `제외사유` 에
표시됩니다.

**Q. 장기급여채무가 0으로 나옵니다.**
`개인별산출` 옆 `장기급여` 시트의 `제외사유` 를 보십시오. 대개 둘 중 하나입니다.
① 명부의 `장기급여 산출대상여부` 가 `N`, ② 기초율의 `장기급여지급률` 시트에
해당 규정명 열이 없음.

**Q. 명부 열 위치를 바꿔도 되나요?**
안 됩니다. 열 배치가 고정되어 있습니다. 바꿔야 한다면 개발자에게
`readers.py` 의 열 표 수정을 요청하십시오.

**Q. 결과를 다시 재현할 수 있나요?**
같은 명부와 같은 기초율을 넣으면 항상 같은 값이 나옵니다. 난수를 쓰지 않습니다.
감사 대응을 위해 산출에 쓴 명부·기초율 파일을 결과와 함께 보관하십시오.
