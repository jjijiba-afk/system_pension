# 사용설명서

담당자용 안내입니다. 파이썬이나 프로그래밍 지식은 필요 없습니다.

## 1. 프로그램 받기

1. GitHub 저장소 → 위쪽 **Actions** 탭
2. 목록에서 `Windows 실행파일 빌드` 중 최근 것(초록 체크 표시) 클릭
3. 페이지 맨 아래 **Artifacts** → `연금계리산출-windows` 클릭해 내려받기
4. 압축(`연금계리산출.zip`)을 풀면 이렇게 들어 있습니다

```
연금계리산출.exe              더블클릭하면 창이 뜹니다. 보통 이것만 쓰면 됩니다
pension-cli.exe               명령프롬프트에서 배치로 돌릴 때
기본자료\
    명부_기본.xlsx            기본 명부 — 재직 275명·퇴직 247명 (실제 평가 사례)
    기초율_기본값.xlsx        표준 퇴직률·승급률·사망률이 채워진 기초율
    명부_양식.xlsx            빈 명부 양식 (작성 예시 두 줄)
    기초율_빈양식.xlsx        처음부터 회사 값으로 채우고 싶을 때
설명서\
    사용설명서.md             이 문서
    계리방법론.md             산출 근거
    지급률규정-작성법.md      퇴직금 규정을 표·수식으로 옮기는 법
```

> 설치 과정이 없습니다. 원하는 폴더에 두고 바로 실행하십시오.
> 처음 실행할 때 "Windows의 PC 보호" 창이 뜨면 **추가 정보 → 실행** 을 누르십시오.
> 서명되지 않은 실행 파일이라 나오는 안내입니다.

### 먼저 한 번 돌려 보기

`기본자료` 의 두 파일만으로 산출이 끝까지 돕니다. 회사 자료를 넣기 전에
화면이 어떻게 흘러가는지 먼저 보십시오.

1. `연금계리산출.exe` 실행
2. 명부에 `기본자료\명부_기본.xlsx`, 기초율에 `기본자료\기초율_기본값.xlsx`
3. **[산출 실행]**

재직 275명·퇴직 247명 규모의 결과 엑셀이 나옵니다. 실제 평가 사례의 명부라
DC 가입자가 섞여 산출대상에서 빠지고, 근속 1년 미만 퇴직자가 지급액 없이 들어오고,
임원의 직군이 '정규직' 으로 적혀 오는 등 **실제 명부에서 마주치는 형태** 가 그대로
들어 있습니다.

> 제도구분 누락 같은 **실제 오류도 그대로** 있습니다. 그래서 이 명부는
> **[검증 오류가 있어도 산출 강행]** 을 켜야 끝까지 돕니다. 검증 리포트가 무엇을
> 잡아내는지 보기에 오히려 좋습니다.

## 2. 준비물 두 가지

### 명부 파일

기존에 쓰던 엑셀 통합문서 그대로 쓰거나, `기본자료\명부_양식.xlsx` 를 복사해
채우십시오. 다음 세 시트가 있어야 합니다.

* `Input` — 산출기준일(C3), 평균임금 체크금액(C5), 직군 규칙(B12부터)
* `재직자명부` — 26행부터 데이터
* `퇴직자명부` — 22행부터 데이터

### 산출 가정 입력

가정은 **화면에서 직접 입력** 하거나, 엑셀 양식을 받아 채우는 두 가지 방법이 있습니다.

#### 방법 A — 입력 화면 (권장)

1. `연금계리산출.exe` 실행
2. **명부 파일** 을 먼저 선택 (직군명을 가져오기 위해)
3. **[산출 가정 입력]** 클릭
4. **직군 매핑** 탭에서 [명부에서 직군 읽어오기] — 명부의 직급·직군을
   산출 묶음으로 배정합니다 ([아래](#직군-매핑) 참고)
5. 탭을 옮겨 가며 값을 넣고 **[저장]**

처음이라면 **[예시 채우기]** 로 흔한 값을 한 벌 깔아 놓고 고치는 편이 빠릅니다.
저장한 파일은 기초율 파일 칸에 자동으로 지정됩니다. 엑셀에서 열어 고친 뒤
**[불러오기]** 로 다시 가져와도 됩니다.

명령행에서 화면만 띄우려면:

```bat
pension-cli assumptions --roster 명부.xlsm
```

검증만 먼저 돌려 보려면 기초율을 **함께** 주십시오. 직군 매핑이 기초율의
`지급규정` 시트에 있으므로, 명부만 주면 calc 와 다른 판정이 나올 수 있습니다.

```bat
pension-cli check 명부.xlsm 기초율.xlsx
```

#### 방법 B — 기본값에서 고치기

`기본자료\기초율_기본값.xlsx` 를 복사해 엑셀에서 고칩니다. 시트마다 빨간
글씨로 **[필수 확인]** 이 적힌 곳이 회사 값으로 바꿔야 하는 자리입니다.

| 시트 | 손봐야 하나 |
|---|---|
| `사망률` | **아니오.** 표준사망률입니다. 남녀를 나눠 씁니다 |
| `할인율` | **예.** 결산일 현재 우량회사채 수익률. 매 결산 달라집니다 |
| `임금상승률` | **예.** 회사의 임금협상 이력·중장기 계획 |
| `승급률` · `퇴직률` | 표준률입니다. **회사 경험률이 있으면 그쪽이 우선입니다** |
| `지급률` | 법정 퇴직금(1년당 30일분)이면 **비워 두십시오**. 누진제·배수제면 채우십시오 |

### 직군마다 가정을 켜고 끄기

직군에 따라 쓰지 않는 가정이 있습니다. **지급규정** 탭 오른쪽 네 칸에서
`반영` / `미반영` 을 고르면 됩니다.

| 가정 | 미반영으로 두는 경우 |
|---|---|
| `Base-up` | 임금이 계약으로 고정된 직군 |
| `승급률` | 호봉표가 없는 계약직 |
| `퇴직률` | 임원을 정년까지 근무한다고 보는 경우 |
| `사망률` | 사망을 별도로 보지 않는 경우 |

미반영은 그 가정의 요율을 0 으로 두는 것과 같습니다. 기초율 표를 직군마다 0 으로
채워도 결과는 같지만, 그러면 **'값이 0 인 것' 과 '적용하지 않기로 한 것' 을
나중에 구별할 수 없습니다.** 근거자료로 남으려면 의도가 드러나야 합니다.

> **퇴직률을 끄면 채무가 커질 수도, 작아질 수도 있습니다.** 퇴직금은
> 중도퇴직해도 그때 지급되므로, 퇴직률을 끄면 지급이 전부 정년 시점으로
> 밀립니다. 그때 채무가 어느 쪽으로 움직이는지는 **임금상승률과 할인율 중
> 어느 쪽이 큰가**로 갈립니다.
>
> * 임금상승률 > 할인율 → 뒤로 밀릴수록 급여가 더 불어나므로 **채무가 커집니다**
> * 임금상승률 < 할인율 → 할인이 더 크게 먹으므로 **채무가 작아집니다**
>
> (이전 판 설명서에는 '항상 줄어든다'고 적혀 있었으나 잘못이었습니다.)

퇴직률·승급률·사망률은 연령 15~70세까지 있습니다. **70세를 넘는 연령은 70세 값을
씁니다** — 표는 계단식으로 읽히므로 마지막 행이 그 이후 전 구간에 적용됩니다.

### 퇴직사유마다 지급이 다를 때

자료요청서 6번에는 지급률이 **세 줄로 갈려** 있습니다.

```
중도퇴직시 퇴직금 지급률
사망시 퇴직금 지급률
정년퇴직시 퇴직금 지급률
```

대개 '동일' 이라고 적어 오지만, 실제로 다른 회사가 적지 않습니다.

| 실제로 받은 문구 | 뜻 |
|---|---|
| `동일, 유족지원금 5,000만원` | 사망하면 5천만원을 더 준다 |
| `근속10년 미만 기본급 3개월분, 10년 이상 5개월분 가산` | 사망 가산이 근속에 따라 다르다 |
| `재직 중 사망으로 퇴직 시 1년 미만도 1년으로 계산` | 사망은 근속을 1년으로 끌어올린다 |
| `정년퇴직시 대표이사 3배, 이사/감사 1.5배` | 정년만 배수가 다르다 |

**퇴직사유** 탭에서 한 줄씩 적습니다. **비워 두면 사유를 가리지 않으므로**,
'동일' 인 회사는 아무것도 안 해도 됩니다.

| 칸 | 넣는 것 |
|---|---|
| `지급률 규정` | 어느 규정에 붙일지 (지급률 표의 열 이름) |
| `퇴직사유` | `중도` / `사망` / `정년` |
| `대체 지급률 규정` | 그 사유일 때 기본 규정 **대신** 쓸 규정 |
| `가산 규정` | 기본 급여에 **더할** 배수를 내는 규정 |
| `가산액(원)` | 정액 가산 (예: 유족지원금 `50000000`) |
| `근속 하한(년)` | 짧은 근속을 끌어올릴 때 (예: `1`) |
| `가산 귀속` | `즉시` / `근속비례` — 비우면 사망은 `즉시`, 나머지는 `근속비례` |

> **가산 귀속이 왜 갈리나.** 재직 중 사망하면 근속이 하루든 20년이든 같은
> 유족지원금을 받습니다. 더 일해도 급여가 늘지 않으므로 문단 70 에 따라 **그
> 시점에 귀속을 멈춥니다** — 지금 근속으로 잰 만큼을 전액 잡습니다. 반대로
> 정년 가산은 정년까지 남아야 받으므로 근속에 따라 쌓아 갑니다.
>
> '10년 미만 3개월분 / 이상 5개월분' 처럼 계단이 있으면, 즉시 귀속이라도
> **지금 올라선 칸까지만** 잡힙니다. 올해 10년째가 되는 사람은 3 → 5 로 오른
> 몫이 당기근무원가로 나옵니다.

사유를 나눈다고 인원이 새거나 겹치지는 않습니다. 중도퇴직률 `w` 와 사망률 `q`
를 연중 균등발생으로 갈라 놓으므로, 두 몫의 합은 종전과 같은 `1-(1-w)(1-q)`
그대로입니다.

### 근속 구간마다 지급률이 다를 때

한 사람의 급여가 근속 구간에 따라 갈리는 회사가 있습니다. 두 가지 모양이 있고,
**명부에서** 지정합니다 (가정 입력이 아닙니다 — 사람마다 다르기 때문입니다).

#### 모양 1 — 호봉제 → 연봉제 전환 (누진 보전)

호봉제(누진제)를 쓰다가 연봉제로 바꾸면서, 전환 전 근속분의 누진 배수를 그대로
보전해 주는 회사가 많습니다. 중간정산을 하지 않았으므로 근속은 이어지고
**배수만** 갈립니다. 자료요청서에 세 열이 있습니다.

| 열 | 넣는 것 |
|---|---|
| `연봉제 전환 추계일` | 전환일 (근거로만 남습니다) |
| `누진적용 근속연수` | 전환 시점까지의 근속 (회사가 계산해 보낸 값) |
| `누진적용 율` | 그 구간의 연 배수 (예: `1.3`) |

근속 17.4년 · 누진근속 7.4년 · 누진율 1.3 이면

```
지급배수 = 7.4 × 1.3  +  (17.4 − 7.4) × 1.0  =  19.62
```

**두 열이 다 있어야 갈립니다.** 한쪽만 채우면 구간을 나누지 않고, 검증에서
알려 줍니다. 근속을 다시 재지 않고 명부의 `누진적용 근속연수` 를 그대로 믿습니다
— 회사가 휴직·군경력을 반영해 계산한 값이라, 날짜만 보고 다시 재면 그 조정이
사라집니다.

> 이 열들은 지금까지 읽히지 않고 있었습니다. 실제 스터디 자료로 재 보니 채무가
> **12.8% 과소계상** 되고 있었습니다.

#### 모양 2 — 같은 사번을 여러 줄로 나눈 명부

임원 퇴직소득 세법한도처럼 기간마다 배수도 기준임금도 다르면, 한 사람이 여러
줄로 옵니다.

```
ER1  …  배수 3.0  임금 13,922,406   비고: 19.12.31이전기간만3배수
ER1  …  배수 2.0  임금 21,250,000   비고: 20.1.1이후기간만 2배수
```

비고에 적힌 글은 프로그램이 해석하지 않습니다. 대신 명부에 두 열을 **추가**
하십시오. 머리글만 맞으면 열 위치는 어디여도 됩니다.

| 열 | 넣는 것 |
|---|---|
| `지급률 기산일` | 그 줄이 담당하는 구간의 시작일 (비우면 근속 기산일부터) |
| `지급률 종료일` | 끝나는 날 **당일 포함** (비우면 퇴직 시점까지) |

이 열이 있으면 사번 중복이 오류가 아니라 **기간 분할** 로 처리됩니다. 사람의
급여는 줄별 구간을 더해 만들어집니다.

> **끝난 구간의 임금은 올리지 않습니다.** 그 줄에 적힌 임금이 이미 그 시점의
> 기준임금이기 때문입니다. 세법한도의 2019년분에 지금 임금상승률을 다시 곱하면
> 법이 정한 기준을 넘깁니다.

구간이 겹치거나 사이가 비면 검증에서 알려 줍니다 — 겹치면 두 번 잡히고, 비면
그 기간이 통째로 빠집니다. 두 경우 다 결과만 봐서는 눈에 띄지 않습니다.

### 장기급여가 단순하지 않을 때

'근속 N년에 닿으면 재직 중에 한 번 준다' 로 안 끝나는 규정이 많습니다.
실제로 받은 것들입니다.

```
10년 : 휴가 3일 , 금 10돈, 특별상여(기본급의 50%)      ← 한 번에 셋
       * 지급일  입사 1/1~9/30 창립기념일(10/1)         ← 도달해도 밀린다
3/6/9년 유급휴가 5·10·15일 → 휴가는 소멸기한 없음       ← 쌓였다가 나갈 때
장기근속 퇴직사원 예우: 20년 이상 근속 순금 8돈          ← 나갈 때만
정년 퇴직사원 예우:     20년 이상 근속 순금 20돈         ← 정년에만
건강검진 2년마다                                        ← 되풀이
```

**[장기급여]** 탭의 표에서, 열 머리 바로 아래 줄들이 그 열을 어떻게 읽을지를
정합니다.

| 칸 | 넣는 것 |
|---|---|
| `지급유형` | `휴가` / `평균임금` / `현물` / `현금` — 표 값의 뜻이 갈립니다 |
| `지급시점` | `근속도달` / `퇴직시` / `정년시` |
| `반복 주기(년)` | 마지막 지급 이후 되풀이하는 주기. 0 이면 한 번만 (건강검진 → `2`) |
| `누적` | 켜면 도달한 지급 시점의 값을 **모두 더합니다** (소멸기한 없는 휴가) |
| `지급일(월-일)` | 창립기념일처럼 날짜가 와야 줄 때 (`10-01`). `근속도달` 에만 씁니다 |

**지급시점** 이 갈리는 이유는 받는 사람이 다르기 때문입니다.

* `근속도달` — 재직 중에 줍니다. 그 시점까지 남아 있어야 받습니다.
* `퇴직시` — 나갈 때 줍니다. **중도퇴직자도 받습니다.**
* `정년시` — 정년퇴직자만 받습니다. 중도에 나가면 못 받습니다.

한 근속연수에 항목이 여럿이면 **[항목 추가]** 로 열을 만듭니다. 항목마다
어느 직군의 급여인지(`어느 직군`)를 고르면 그 직군에 얹힙니다.

```
근속연수 | 정규직     | 금        | 특별상여
─────────┼────────────┼───────────┼──────────
어느 직군│ 정규직     │ 정규직    │ 정규직
지급유형 │ 휴가       │ 현물      │ 평균임금
지급시점 │ 근속도달   │ 퇴직시    │ 근속도달
지급일   │ 10-01      │           │
─────────┼────────────┼───────────┼──────────
10       │ 3          │ 5,000,000 │ 0.5
```

> **귀속은 그 급여를 벌게 한 근무기간에 고르게 나눕니다**(문단 72). '20년
> 이상이면 순금 8돈' 이라면 20년에 걸쳐 쌓이지, 20년째에 한 번에 잡히지
> 않습니다. 그래야 채무가 한 해에 튀지 않습니다.

아직 못 담는 것: **자녀 학자금** 같이 근속이 아니라 부양가족 수로 정해지는
급여입니다. 명부에 그 자료가 없어 근속만으로는 산출할 수 없습니다.

### 시스템 등록 — 금리표·표준률을 한 번만 넣어 두기

한 결산기에 여러 단체를 산출할 때 **금리표는 모두 같습니다.** 결산일이 같으면
우량회사채 수익률도 같기 때문입니다. 표준률도 단체마다 다시 만들 이유가 없습니다.

단체마다 파일을 다시 찾아 지정하면, 스무 단체를 산출할 때 같은 금리표를 스무 번
고르는 셈입니다. 그중 한 번이라도 다른 파일을 집으면 그 단체만 할인율이 달라지고,
**눈에 띄지도 않습니다.**

산출 가정 화면 맨 위 **시스템 등록 자료** 줄에서 한 번 등록해 두면 이후 모든
산출에서 목록으로 골라 쓸 수 있습니다.

| 버튼 | 하는 일 |
|---|---|
| 표준률 [등록] | 표준 기초율 워크북을 등록 |
| 표준률 [불러오기] | 등록된 표준률을 화면으로 가져옴 |
| 금리표 [등록] | KIS-Net 등 만기별 금리표를 등록 |
| 금리표 [적용] | 고른 등급의 현물이자율 곡선을 `할인율` 탭에 채움 |

**불러온 뒤 값을 고쳐도 됩니다.** 등록된 것은 출발점이지 확정이 아닙니다.
표준률을 불러와도 저장 경로는 비워 두므로, [저장] 이 등록 자료를 덮어써서 다른
단체까지 바뀌는 일은 없습니다.

명령행에서도 됩니다.

```bat
pension-cli library add 금리표 KIS금리_20251231.xlsx --name KIS_20251231
pension-cli library add 표준률 표준률_2025.xlsx
pension-cli library list
```

등록 파일은 `%APPDATA%\연금계리산출` 에 **복사** 됩니다. 원본을 참조만 하면
담당자가 그 파일을 옮겼을 때 이후 산출이 조용히 실패하기 때문입니다.

### 단일할인율 — 수익률곡선기법

금리표를 넣으면 만기별로 다른 이자율(현물이자율)로 할인합니다. 그런데 주석에는
할인율을 **하나만** 적어야 합니다.

임의로 한 만기의 이자율을 고르는 대신, **곡선으로 할인한 채무와 같은 현재가치를
내는 단일 이자율** 을 역산합니다.

```
Σ 급여(t) ÷ (1 + r)^t  =  곡선으로 할인한 확정급여채무
```

K-IFRS 1019 문단 85 의 "급여지급의 예상 시기와 금액을 반영하는 단일 가중평균
할인율" 이 이것입니다. 결과 엑셀 `산출요약` 에 이 값이 **적용 할인율(단일할인율)**
로 나오고, 참고로 듀레이션 시점 현물이자율도 함께 적힙니다.

> 두 값은 꽤 다를 수 있습니다. 실제 사례에서 듀레이션(5.9년) 시점 이자율은
> 3.688% 였지만 단일할인율은 4.233% 였습니다. 곡선이 우상향일수록 벌어집니다.
> **이자원가도 단일할인율로 계산합니다.**

### 등급 선택

등급을 지정하지 않으면 AA0 → AA+ → AA- 순으로 찾습니다. 무엇을 우량회사채로
볼지는 회계정책이므로 회사가 정합니다.

빈 양식부터 시작하려면 `기초율_빈양식.xlsx` 를 쓰거나 화면의
**[기초율 양식 새로 만들기]** 를 누르십시오.

#### 탭·시트별로 채울 내용

입력 화면은 **네 묶음** 입니다. 한 묶음 안의 표는 세로로 쌓이고, 제목을 누르면
접었다 펴집니다. 접힌 채로도 제목 옆에 몇 줄 채워졌는지 보입니다.

**[직군]** — 직군을 어떻게 나눌지와, 직군마다 무엇을 적용할지

| 구획 | 무엇을 넣나 |
|---|---|
| `직군 매핑` | 명부의 직급·직군을 어느 묶음으로 볼지 |
| `지급규정` | 직군별 정년·근속 산정·단수 처리·반올림, 그리고 **가정별 반영 여부** |
| `Base-up` | 승진·승급을 뺀 공통 임금인상률. 회사의 임금협상 이력에서 정합니다 |

**[기초율]** — 금리표·표준률에서 **불러오는** 표들

| 구획 | 무엇을 넣나 |
|---|---|
| `할인율` | 결산일 현재 우량회사채 수익률. 한 줄이면 전 기간 단일 |
| `승급률` | 호봉·승진에 따른 인상률. 조회 기준을 연령/근속 중 고를 수 있습니다 |
| `퇴직률` | 연간 중도퇴직률. 과거 3~5년 경험률 권장 |
| `사망률` | 경험생명표 등의 `qx` |

> 승급률·퇴직률·사망률은 [표준률 불러오기] 한 번으로 한꺼번에 채워집니다.
> **직군마다 쓸지 말지는 [직군] 탭의 지급규정에서 켜고 끕니다** — 표를 직군별로
> 0 으로 채우지 마십시오. 그러면 '값이 0 인 것' 과 '적용하지 않기로 한 것' 을
> 나중에 구별할 수 없습니다.

**[퇴직급여]**

| 구획 | 무엇을 넣나 |
|---|---|
| `지급률` | 월평균임금 대비 배수. **법정 퇴직금만 쓴다면 비워 두십시오** |
| `퇴직사유별 차등` | 중도퇴직·사망·정년퇴직의 지급이 다를 때만 |

지급률 표는 **열 머리 아래에 그 열을 읽는 방법**(누적/누진/수식과 수식)이
함께 있습니다. 표만 보고는 값이 누적 배수인지 구간 배수인지 알 수 없어, 전에는
다른 탭과 번갈아 봐야 했습니다.

**[항목 추가]** 로 직군이 아닌 이름의 지급률을 만들 수 있습니다 — `사망가산`,
`정년배수` 처럼요. `퇴직사유별 차등` 의 `대체 지급률 규정`·`가산 규정` 에서
그 이름을 고릅니다.

**[장기급여]** — 표 한 장입니다. 열이 곧 지급 항목이고, 열 머리 아래에서
지급유형·지급시점·반복 주기·누적·지급일을 고릅니다.

> **누진제 퇴직금이라면 지급률 표의 `방식` 줄에서 `누진` 으로 바꾸십시오.**
> 표에 구간별 연 배수만 적으면 됩니다. 자세한 내용은
> [지급률규정-작성법.md](지급률규정-작성법.md) 를 보십시오.

> **열 이름이 중요합니다.** `Input` 시트의 규정명 칸(G~N열)이나 명부의 규정 칼럼에
> 적은 이름과 기초율 시트의 열 머리글이 **글자 하나까지 같아야** 합니다.
> 다르면 해당 인원의 산출 결과에 "규정을 찾을 수 없음" 이 표시됩니다.

> **표는 계단식으로 읽습니다.** 퇴직률 시트에 20·35·50세 행만 있으면
> 27세인 사람은 20세 행 값을 씁니다. 모든 연령을 다 적을 필요는 없습니다.

### 직군 매핑

명부의 `직군` 열에 무엇이 들어올지는 회사가 정합니다. 실제로 받아 본 파일만 해도
이렇게 갈렸습니다.

| 명부 직군 | 임직원구분 | 뜻 |
|---|---|---|
| `정규직` / `계약직` | `직원` / `임원` | 고용형태가 그대로 들어옴 |
| `사원` / `과장` / `대표이사` | `정사원` / `촉탁사원` / `임원（주재원）` | **직급** 이 들어옴 |
| `정규직` | `Senior` / `Master` / `T직` | 임직원구분 칸에 **직급** 이 들어옴 |

기초율(퇴직률·승급률·지급률)은 이 낱낱의 직급마다 만들지 않습니다. 비슷한 것끼리
묶고 그 단위로 세웁니다. 기본 묶음은 **정규직 / 계약직 / 임원** 입니다.

**묶음 이름은 바꿀 수 있습니다.** 생산직과 관리직의 퇴직률이 확연히 다른 회사라면
위쪽 `직군별 규정` 칸에 이렇게 적으십시오.

```
생산직, 관리직, 일반직, 계약직, 임원
```

적용을 누르면 모든 가정 표의 열이 그 이름으로 다시 만들어지고, 매핑 표의 배정
칸에서도 그 이름을 고를 수 있게 됩니다. [기본값] 은 정규직/계약직/임원으로
되돌립니다.

**배정은 제안만 하고 확정하지 않습니다.** [제안대로 채우기] 는 `촉탁`·`기간제`·
`파견` 같은 말이 들어가면 계약직, `이사`·`대표`·`전무` 면 임원으로 찍어 줄 뿐입니다.
같은 '촉탁사원' 이라도 정년 후 재고용이면 계약직, 임원 예우 재고용이면 임원인
회사가 있으므로 **반드시 규정을 보고 확인하십시오.**

> **묶음을 잘게 나눌수록 좋은 것이 아닙니다.** 구간별 인원이 줄면 경험률의 통계적
> 신뢰도가 떨어집니다. 퇴직률·승급률·지급률이 **실제로 다른** 단위로만 나누십시오.

배정 결과는 저장 시 기초율 파일의 `지급규정` 시트에 `명부직군` · `임직원구분` ·
`변환직군명` 세 열로 적힙니다. **산출할 때 이 시트가 있으면 명부의 `Input` 시트보다
우선합니다.** `Input` 은 회사가 채워 보내는 칸이라 비어 있거나 직군만 적혀 오는
일이 잦고, `지급규정` 은 계리 담당자가 규정을 보고 확정한 것이기 때문입니다.

조회는 좁은 것부터 순서대로 맞춰 봅니다.

1. 직군 + 임직원구분 원문 (`과장` + `촉탁사원`)
2. 직군 + 정규화된 임직원구분 (`과장` + `직원`)
3. 임직원구분만 → 4. 직군만

그래서 `과장/정사원` 과 `과장/촉탁사원` 을 서로 다른 묶음에 넣을 수 있습니다.
임직원구분을 정규화하면 `임원`/`직원` 둘뿐이라 이 구분이 사라지기 때문에 원문을
먼저 봅니다.

## 아이패드에서 쓰기

두 가지 방법이 있습니다. 어느 쪽이든 App Store·개발자 계정은 필요 없습니다.

### 방법 1 — 홈 화면에 설치하는 앱 (권장)

압축파일의 `아이패드웹앱` 폴더를 사내 정적 웹서버(HTTPS)에 올리고,
아이패드 Safari 로 그 주소를 연 뒤 **공유 버튼 → 홈 화면에 추가** 를 누르십시오.

* 앱 아이콘이 생기고 전체화면 앱으로 열립니다
* **모든 계산이 아이패드 안에서** 이루어집니다 — 명부가 기기 밖으로 나가지 않습니다
* 한 번 연 뒤에는 **오프라인에서도** 동작합니다 (전부 캐시됨, 약 14MB)
* 외부 CDN 을 쓰지 않으므로 인터넷이 막힌 사내망에서도 됩니다

같은 산출 엔진이 WebAssembly 로 브라우저 안에서 돕니다. 실제 명부(재직 275명)로
PC 산출과 결과가 원 단위까지 같은 것을 확인했습니다.

웹앱에도 PC 프로그램의 화면이 그대로 있습니다.

* **단체 (화면 맨 위)** — 탭보다 위, 가장 먼저 고르는 것입니다. 산출 내역이
  이 단체 안에 쌓이고, 전기 산출 목록에도 **이 단체 것만** 뜹니다. 전기
  확정급여채무를 다른 단체 것으로 끌어오면 증감분석이 통째로 틀리는데,
  목록에 뜬 이름만 보고는 알아채기 어렵기 때문입니다. [＋ 새 단체] 로
  늘리고, [이름 바꾸기] 로 고치면 안에 든 산출이 그대로 따라갑니다.
  [삭제] 는 산출이 남아 있으면 몇 건인지 세어 한 번 더 물어봅니다.
  단체를 만들지 않고 쓰면 `기본 단체` 하나에 모두 들어가므로, 예전처럼
  써도 달라지는 것은 없습니다. 예전 판에서 저장해 둔 산출은 앱을 열 때
  `기본 단체` 안으로 자동으로 옮겨집니다.

  금리표·표준률은 결산기가 같으면 어느 단체든 같은 것을 쓰므로 자료실에
  **공용으로** 둡니다. 단체별로 갈리는 것은 산출 내역뿐입니다.
* **산출 탭** — 늘 쓰는 것은 `1. 명부 파일` 과 `2. 기초율` 둘뿐이라 이 둘만
  펼쳐 두고, `기준일`·`옵션`·`전기 산출 결과`·`사외적립자산` 은 접어 두었습니다.
  **접힌 채로도 제목 옆에 지금 무엇이 설정돼 있는지** 나옵니다 — `명부 값 사용`,
  `2412 1번단체`, `기말 129억` 처럼요. 전기 채무를 넣어 둔 것을 잊고 다시 넣거나,
  넣은 줄 알고 안 넣는 일을 막기 위한 것입니다. [산출 실행] 은 화면 아래에
  붙어 있어 얼마나 펼쳐도 손이 닿습니다.
* **계리평가 보고서 (인쇄 → PDF)** — 산출을 마치면 결과 아래에서 퇴직급여·
  장기급여 평가보고서를 만들 수 있습니다. 표지 → 평가개요 → 평가 결과 요약 →
  공시사항(확정급여채무·사외적립자산 변동표, 재측정요소 분석, 차년도 예상
  비용) → 민감도 분석 → 주석(규정 요약, 경과기간별 만기분석, 차년도 예상
  기여금) → 첨부(임직원 분포, 승급률·퇴직률·사망률·지급률 표 전체) → 용어
  정리까지, K-IFRS 1019 문단 135~147 의 공시 요구 항목을 모두 담았습니다.
  장기급여 보고서는 문단 153~158(재측정 당기손익 인식, 간이 공시)을 따릅니다.
  미리보기에서 [인쇄 / PDF 저장] 을 누르면 아이패드는 인쇄 화면의 공유 →
  **파일에 저장**, PC 는 대상 프린터에서 **PDF로 저장**을 고르면 됩니다.
  보고서 숫자는 산출 엔진 결과를 그대로 옮긴 것이라 화면 요약·결과 엑셀과
  원 단위까지 같습니다. 전기 산출을 연결하고 사외적립자산을 채우면 모든
  표가 완성되고, 비워 두면 그 표에 이유가 적힙니다.
* **사번 조회 (개인별 산출 근거)** — 산출 결과 아래에서 사번(또는 성명)을
  넣으면 **그 사람만 같은 명부·기초율로 다시 산출**해서 인적사항, 적용한
  규정·가정, 연차·퇴직사유별 계산 근거(연령·근속·임금·퇴직률·사망률·
  잔존확률·지급액·귀속액·할인계수·채무 기여)를 한 줄씩 보여줍니다.
  근거 줄의 합이 곧 그 사람의 확정급여채무라 감사인이 손으로 재계산할 수
  있고, 전체 산출과 원 단위까지 같습니다. 장기급여 대상자는 지급 시점별
  근거도 함께 나옵니다. [산출 내역]의 저장된 산출에서도 [결과 보기] 안에서
  같은 조회를 할 수 있습니다.
* **산출가정 입력 탭** — [직군] · [기초율] · [퇴직급여] · [장기급여] 네
  묶음입니다. 한 묶음 안의 표는 세로로 쌓이고 제목을 눌러 접었다 폅니다.
  접힌 구획도 제목 옆에 몇 줄 채워졌는지 보입니다.
  저장하면 PC 와 같은 서식의 `산출가정.xlsx` 가 내려오고, 산출 탭에 바로
  연결됩니다. 입력 중이던 내용은 브라우저에 임시 저장되어 앱을 닫아도
  남습니다.
* **자료실 탭** — 여러 결산에 걸쳐 쓰는 것을 모아 둔 곳입니다. 가정세트 ·
  금리표 · 명부 · 표준률을 등록해 두면 이 기기의 브라우저 안(IndexedDB)에
  저장되어, 다른 단체를 산출할 때도 목록에서 골라 쓸 수 있습니다. 따로
  지정하지 않으면 최근 등록분이 기본으로 잡히고, 등록이 없어도 내장
  표준률(15~70세)은 항상 쓸 수 있습니다. 구획마다 제목 옆에 **몇 개가
  들어 있고 어느 것이 기본인지** 적혀 있어 접어 둔 채로도 확인됩니다.
  같은 탭 아래에 [시험 명부 만들기] 와 [보관함] 이 함께 있습니다 — 셋 다
  "산출 한 건"이 아니라 "앱에 쌓아 두는 자료"라 한 곳에 모았습니다.
* **산출 내역 탭** — 지금 고른 단체의 산출 목록입니다. 산출을 마친 뒤 이름을
  붙여 저장하면 명부·산출가정·결과가 통째로 기기에 남습니다. 단체가 갈라져
  있으므로 "2412" 처럼 **결산기만** 적어도 됩니다. 다음 결산 때
  [입력 불러오기] 로 전기 입력을 그대로 끌어와 재산출하거나, 저장된 결과
  요약·엑셀을 다시 볼 수 있습니다. 같은 이름으로 저장하면 덮어씁니다.
* **전기 산출 연결** — 산출 탭 5번 칸에서 저장된 산출을 고르면 전기말
  확정급여채무·할인율·근무원가가 그대로 채워지고, **전기 기초율까지 함께
  넘어가** 증감분석이 경험조정과 가정변경효과를 나눠 계산합니다. 손으로
  옮겨 적다 자릿수를 틀릴 일이 없습니다. 목록에는 지금 고른 단체의 산출만
  뜨므로 남의 회사 것을 잘못 고를 일도 없습니다.
* **저장된 명부** — 올렸던 명부를 목록에 두고 다음 결산에 그대로 꺼내
  씁니다. 산출 탭에서 [이 파일을 목록에 저장] 을 누르거나 자료실
  탭에서 등록하면 됩니다. `.xls` 로 받은 명부는 서식 그대로 보관됩니다.
* **가정세트** — 지금 화면의 산출가정 전체(지급률·지급규정·직군 매핑까지)를
  이름 붙여 저장합니다. 같은 회사를 매년 산출하거나 규정이 같은 계열사를
  여럿 맡을 때 [불러오기] 한 번으로 끝납니다. 산출가정 입력 탭의
  [현재 가정 저장] 또는 자료실 탭에서 관리합니다.
* **산출기준일 · 산출 시작일** — 산출 탭 3번 칸에서 넣습니다. 기준일을
  넣으면 **명부를 고치지 않고** 그 날짜로 산출합니다(가결산·시산). 시작일
  (직전 결산일)을 넣으면 증감분석의 이자원가를 그 기간으로 환산합니다 —
  결산기가 바뀌어 기간이 1년이 아닌 회차에서 이자원가가 부풀지 않습니다.
* **시험 명부 만들기** (자료실 탭) — 난수로 만든 시험용 명부 세 벌(재직 290명 안팎)을
  그 자리에서 만듭니다. 표준 / 복합제도(DC·중간정산·임금피크·정년초과
  재고용·전입) / 자료불량(검증 리포트 확인용) 세 가지이고, 명부마다 짝이
  되는 기초율과 **특이사항 안내문**이 함께 나옵니다. 씨앗이 같으면 언제
  만들어도 같은 명부라 산출 결과를 비교할 수 있습니다. PC 에서는
  `pension samples 기본자료 --cases` 로 같은 것을 만듭니다.

  시험 명부에는 담당자가 채워 보낸 것처럼 **`1)일반사항` 도 들어 있습니다.**
  회계기간·신용등급·퇴직급여 변동내역·사외적립자산(변동내역과 세부내역)·
  장기근속 지급액이 그것인데, 명부를 올리면 그대로 화면에 들어가 다시 적을
  일이 없습니다. 금액은 그 명부의 퇴직자 지급액과 맞춰 두었고 사외적립자산의
  검산줄(기초 + 유입 − 유출 = 기말)이 0 원으로 떨어지므로, 증감표가 어긋나면
  시험 자료가 아니라 산출 쪽을 보시면 됩니다.

#### 기본으로 들어 있는 가정

빈 화면에서 시작해도 말이 되는 산출이 나오도록 두 가지를 미리 넣어 두었습니다.

* **Base-up 전 기간 2%** — 마지막 줄의 값이 이후 전 구간에 적용되므로
  한 줄(1년차 2%)이 곧 전 기간 2%입니다. 회사의 임금협상 이력이 있으면
  그쪽이 우선입니다.
* **지급률은 법정** — 지급률 규정의 기본 방식이 `법정` 입니다. 지급률 표를
  비워 두면 법정 퇴직금(30일 평균임금 × 근속연수)이 적용되고, **표에 값을
  넣으면 그 값이 그대로 쓰입니다.** 누진제·수식 규정일 때만 방식을 바꾸면
  됩니다.

#### 사외적립자산과 순확정급여부채

산출 탭 6번 칸에 신탁 명세서의 네 숫자(기초 공정가치·부담금 납입액·자산에서
지급한 퇴직급여·기말 공정가치)를 넣으면 자산 증감표와 **순확정급여부채**가
함께 나옵니다.

* 이자수익은 **채무와 같은 할인율**로 계산합니다(문단 125). 자산의 실제
  수익률이 아닙니다.
* 자산 재측정손익은 기말 잔액에 맞춘 나머지이며 기타포괄손익입니다.
* 순확정급여부채 = 확정급여채무 − 사외적립자산 공정가치.
* 자산이 채무를 넘으면(초과적립) 경고를 남깁니다 — 자산인식상한(문단 64)은
  별도 판단이 필요해 이 프로그램이 적용하지 않습니다.

#### 과거근무원가와 정산손익

전기 기초율을 연결하면 **지급률 규정이 바뀐 만큼**을 자동으로 과거근무원가로
떼어 냅니다. 제도개정 효과는 당기손익, 보험수리적손익은 기타포괄손익이라
섞이면 영업이익이 달라지기 때문입니다. 정년 연장처럼 지급률 밖의 개정은
산출 탭 5번 칸에 직접 넣으세요.

중간정산·전출로 **소멸한 채무**를 넣으면 지급액과의 차이를 정산손익으로
인식합니다(문단 109~112). 전기 개인별 결과에서 해당자의 채무를 합쳐 넣으면
됩니다.

#### 명부의 개인별 정년연령

명부 `정년연령`(22열)에 값이 있으면 **직군 규정보다 우선**합니다. 계약으로
정년을 달리 정한 임원처럼 직군 한 줄로 담을 수 없는 경우에 씁니다. 임금피크
연령이 더 이르면 그쪽이 이깁니다.

#### 산출에 반영되지 않는 칸 — 경고로 알려 줍니다

| 칸 | 지금 동작 |
|---|---|
| `추가지급 기본급`(35열) | **모든 퇴직 시점**의 지급액에 정액으로 더해집니다. 중도퇴직·정년퇴직을 구분하지 않으므로 규정과 맞는지 확인하십시오 |
| `명예퇴직 산정용 임금`(12열) | 산출에 **반영되지 않습니다.** 명예퇴직 급여를 채무에 넣으려면 지급률 규정(수식)으로 옮기십시오 |
| `전입일`(21열) | 근속 기산에 쓰지 않습니다. 근속 승계 여부는 입사일에 이미 반영돼 있어야 합니다 |

값이 들어 있으면 검증 리포트에 경고가 남습니다.

#### 보관함 — 기기 밖에 저장

앱 안의 자료는 브라우저 저장소에 있어 **Safari 방문기록·웹사이트 데이터를
지우거나 기기를 바꾸면 함께 사라집니다.** 그래서 등록 자료(금리표·표준률·명부)와
산출 내역 전부를 파일 하나로 내보낼 수 있게 했습니다.

자료실 탭 아래 [보관함 내보내기] → `연금계리보관함_YYYYMMDD.zip` 이
내려옵니다 → 공유 → **파일에 저장 → iCloud Drive**. 되살릴 때는 그 파일을 골라
[가져오기(합치기)] 또는 [전체 교체] 를 누르면 됩니다. 다른 아이패드·PC 에서도
같은 파일로 그대로 복원되므로, 결산이 끝날 때마다 한 번씩 내보내 두십시오.

#### 새 버전을 올렸는데 화면이 그대로일 때

앱은 오프라인으로 쓰려고 파일 전부를 기기에 캐시해 둡니다. 새 빌드를 올려도
잠깐은 옛 화면이 돌 수 있습니다. 화면 맨 아래 **빌드 `xxxxxxxxxxxx`** 값이
올린 빌드의 값과 같은지 보십시오(빌드할 때 `캐시 버전`으로 찍히는 값과 같습니다).

다르면 — 홈 화면 앱은 **완전히 닫았다가**(앱 전환기에서 위로 밀어 없애기) 다시
열고, Safari 탭이면 새로고침하십시오. 한 번에 안 바뀌면 한 번 더 하시면 됩니다
(첫 실행에서 새 캐시를 받고, 다음 실행부터 그것을 씁니다).

> 홈 화면 설치와 오프라인 캐시는 HTTPS 주소에서만 동작합니다(브라우저 규약).
> HTTP 로만 열 수 있는 환경이면 Safari 즐겨찾기로 쓰시면 됩니다 — 계산은
> 똑같이 기기 안에서 됩니다.

### 방법 2 — 사무실 PC 를 서버로

PC 에서 한 줄을 실행하고, 아이패드 Safari 로 화면에 표시되는 주소에 접속합니다.

```bat
pension-cli web --host 0.0.0.0
```

* 계산은 PC 에서, 아이패드는 화면 역할만 합니다
* 명부는 산출 즉시 지워지고 서버 PC 에 파일로 남지 않습니다
* **인증이 없으므로 사내 네트워크 밖(인터넷)으로 열지 마십시오**

### App Store 앱은?

기술적으로 가능하지만 권하지 않습니다. 엔진을 스위프트로 다시 쓰거나 무겁게
감싸야 하고, 애플 개발자 계정(연 $99)과 심사가 필요합니다. 위 두 방법이 같은
결과를 더 적은 비용으로 냅니다.

## 3. 산출하기

1. `연금계리산출.exe` 실행
2. **1. 입력 파일** — 명부, 기초율, 결과 저장 위치를 지정
   (명부를 고르면 결과 경로는 자동으로 채워집니다)
3. **2. 산출 옵션** — 보통 그대로 두십시오
4. **3. 전기 산출 결과** — 작년 수치가 있으면 넣으십시오. 최초 평가면 비워 둡니다
   * 전기말 확정급여채무, 전기말 할인율
   * **전기 기초율 파일** 까지 넣으면 보험수리적손익이 경험조정과 가정변경으로
     나뉩니다. 주석 공시에 필요한 수치입니다
5. **[산출 실행]** 클릭
6. 아래 로그에 진행상황과 결과 요약이 나옵니다
7. **[결과 폴더 열기]** 로 엑셀을 여십시오

## 4. 오류가 났을 때

### "명부 검증에서 오류 N건이 발견되어 산출을 중단했습니다"

명부에 고쳐야 할 곳이 있습니다. 로그에 이렇게 나옵니다.

```
[ERROR] JAE_WAGE_BELOW_CHECK (재직자명부!K28) 사번=A003: 30일 평균임금 100원이 체크금액 1,000,000원 미만입니다
```

읽는 법: `재직자명부` 시트의 **K열 28행** 을 보라는 뜻입니다. 엑셀에서 그 칸으로
바로 가면 됩니다.

**오류를 모두 한 번에 보여 주므로**, 로그에 나온 곳을 전부 고친 뒤 한 번만 다시
돌리면 됩니다.

### 자주 나오는 오류

| 코드 | 뜻 | 조치 |
|---|---|---|
| `JAE_JOB_GROUP_UNKNOWN` | 명부의 직군에 맞는 규칙이 없음 | **직군 매핑** 탭에서 [명부에서 직군 읽어오기] 를 다시 누르십시오. 명부가 바뀌어 새 직급이 생기면 배정되지 않은 채 남습니다 |
| `JAE_DUP_ID` | 사번 중복 | 메시지에 중복된 행 번호가 모두 나옵니다 |
| `JAE_BIRTH_DATE` | 생년월일을 해석 못 함 | `YYYY-MM-DD` 로 고치십시오 |
| `JAE_WAGE_BELOW_CHECK` | 평균임금이 체크금액 미만 | 임금을 확인하거나 `Input` C5의 체크금액을 조정 |
| `JAE_PLAN_MISSING` | 제도구분 공란 | `DB` / `DC` / `퇴직금제도` 중 하나 |
| `JAE_HIRE_AFTER_BASE` | 입사일이 산출기준일보다 늦음 | 기준일 이후 입사자는 명부에서 빼십시오 |
| `TOI_REASON_MISSING` | 퇴직사유 미입력 | 1~6 중 하나 (1:중도 2:사망 3:DC전환 4:정년 5:전출 6:사업처분) |
| `TOI_FUND_OVER_TOTAL` | 사외자산 지급액 > 총지급액 | 금액을 확인하십시오 |

### 검토용으로 일단 돌려보고 싶다면

**[검증 오류가 있어도 산출 강행]** 을 켜십시오. 다만 그 결과는 **검토용입니다.**
확정 공시 전에는 반드시 명부를 고치고 다시 돌리십시오.

### 경고(WARNING)는 무엇인가

산출은 되지만 담당자가 확인해야 하는 항목입니다. 자동으로 판단할 수 없어서
알려 드리는 것입니다.

* `JAE_NRA_NOT_FUTURE` — 정년을 이미 넘긴 사람. `Input` F열의 가산 연수를 확인
* `TOI_REASON_AMBIGUOUS` — 임금피크 중간정산의 분류가 VBA와 시트 수식에서 갈림
* `XREF_ID_IN_BOTH` — 같은 사번이 재직·퇴직 양쪽에 있음 (DC 전환자면 정상)

## 5. 결과 엑셀 읽기

| 시트 | 쓸 곳 |
|---|---|
| `산출요약` | 재무제표 주석의 기본 수치. 인원·DBO·근무원가·이자원가·듀레이션 |
| `증감분석` | 주석의 확정급여채무 변동 내역 표 |
| `민감도분석` | 주석의 민감도 공시 |
| `기대현금흐름` | 연도별 기대 급여지급액·현가계수. **단일할인율·듀레이션의 검산 근거** |
| `적용가정` | 산출에 실제 쓴 가정 전체의 사본. 결과 파일 혼자서 근거자료가 되도록 |
| `개인별산출` | 검산용. 원가코드별 배분에도 씁니다 |
| `장기급여` | 기타장기종업원급여 (보험수리적손익을 당기손익으로 인식) |
| `검증리포트` | 명부 이슈 전체. 필터가 걸려 있습니다 |
| `UpLoad_Jae` / `UpLoad_Toi` | 기존 VBA가 만들던 업로드 명부와 같은 형식 |

### 결과가 맞는지 빠르게 보는 법

**`산출요약` 의 확정급여채무 ÷ 퇴직급여추계액** 을 계산해 보십시오.
통상 **0.7 ~ 1.1** 입니다. 크게 벗어나면:

* 1보다 많이 크다 → 임금상승률이 할인율보다 지나치게 높지 않은지
* 0.7보다 작다 → 정년연령이 너무 멀지 않은지, 할인율이 과도하지 않은지

**민감도분석의 할인율 ±0.5%p 변동률** 은 대략 `듀레이션 × 0.5%` 여야 합니다.
듀레이션 9년이면 약 4.5%. 크게 다르면 기초율을 다시 보십시오.

### 개인별 결과를 따로 받고 싶을 때

개인별 결과는 산출결과 엑셀 안에 `개인별산출` 시트로 이미 들어갑니다. 원가배분이나
부서 확인용으로 **별도 파일**이 필요하면 두 가지 방법이 있습니다.

* GUI — `2. 산출 옵션` 의 **[개인별 결과 별도 파일로 저장]** 체크
  → 결과 파일 옆에 `<결과파일명>_개인별.xlsx` 로 함께 저장됩니다
* 명령행 — `pension-cli members 명부.xlsm 기초율.xlsx -o 개인별결과.xlsx`

파일에는 시트 세 개가 들어갑니다.

| 시트 | 내용 |
|---|---|
| `개인별산출` | 1인 1행. 퇴직급여와 장기급여를 사번 기준으로 합쳐 놓았습니다 |
| `원가코드별집계` | 명부 `원가코드` 열 기준 집계 — 제조원가/판관비 배분에 씁니다 |
| `직군별집계` | 직군 기준 집계 |

`개인별산출` 시트는 명부를 다시 열지 않아도 되도록 생년월일·입사일·제도구분·
원가코드·적용 규정명까지 함께 담습니다. 머리글에 자동 필터가 걸려 있어 부서별로
걸러 내기 편합니다.

> **회색으로 칠해진 행은 산출에서 빠진 사람입니다**(DC 가입자 등). 행을 지우지 않고
> 남겨 두는 이유는 인원 대사를 위해서입니다. 합계는 이들을 0으로 보고 더합니다.

> **`추계액대비` 열을 확인하십시오.** DBO ÷ 퇴직급여추계액이며 통상 0.7~1.1 입니다.
> 특정 인원만 크게 벗어나면 그 사람의 정년연령이나 지급률 규정을 확인하세요.

## 6. 배치로 돌리기 (선택)

명령프롬프트에서:

```cmd
pension-cli calc 명부.xlsm 기초율.xlsx -o 산출결과.xlsx
pension-cli check 명부.xlsm -o 검증결과.csv
pension-cli template 기초율.xlsx --roster 명부.xlsm

REM 개인별 결과만 별도 엑셀로
pension-cli members 명부.xlsm 기초율.xlsx -o 개인별결과.xlsx
pension-cli upload 명부.xlsm -o 업로드명부.xlsx
```

전기 수치를 넣으려면:

```cmd
pension-cli calc 명부.xlsm 기초율.xlsx -o 결과.xlsx ^
    --prior-dbo 8412530000 --prior-rate 4.8% --prior-assumptions 기초율_전기.xlsx
```

검증 오류가 있으면 종료 코드 `2` 로 끝나므로, 배치 스크립트에서 판정할 수 있습니다.

## 7. 자주 묻는 것

**Q. DC 가입자가 산출에서 빠졌습니다.**
정상입니다. 확정기여제도는 부담금을 납입하면 의무가 끝나므로 확정급여채무가
생기지 않습니다(K-IFRS 1019호 문단 51). `개인별산출` 시트의 `제외사유` 에
표시됩니다.

**Q. 장기급여채무가 0으로 나옵니다.**
`개인별산출` 옆 `장기급여` 시트의 `제외사유` 를 보십시오. 대개 둘 중 하나입니다.
① 명부의 `장기급여 산출대상여부` 가 `N`, ② 기초율의 `장기급여지급률` 시트에
해당 규정명 열이 없음.

**Q. 명부 열 위치를 바꿔도 되나요?**
안 됩니다. 열 배치가 고정되어 있습니다. 바꿔야 한다면 개발자에게
`readers.py` 의 열 표 수정을 요청하십시오.

**Q. 결과를 다시 재현할 수 있나요?**
같은 명부와 같은 기초율을 넣으면 항상 같은 값이 나옵니다. 난수를 쓰지 않습니다.
감사 대응을 위해 산출에 쓴 명부·기초율 파일을 결과와 함께 보관하십시오.
