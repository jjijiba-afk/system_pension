# 지급률 규정 작성법

퇴직급여 지급률은 **30일 평균임금에 곱할 배수** 다. 근속 10년에 배수 12.0 이면
퇴직급여 = 월평균임금 × 12.0 이다.

작성 방식은 세 가지이고, `지급률규정` 시트의 `방식` 열에서 고른다.

| 방식 | 언제 쓰나 | 코드 필요 |
|---|---|---|
| **누적** | 규정에 근속연수별 배수가 표로 적혀 있을 때 | 없음 |
| **누진** | 누진제 — 구간마다 연 배수가 다를 때 | 없음 |
| **수식** | 위 둘로 담기 어려운 조건부 규정 | 엑셀 문법 |

> **권장 순서는 누진 → 누적 → 수식이다.** 국내 퇴직금 규정은 대부분 누진 구간표로
> 그대로 옮겨진다. 수식은 표로 안 되는 것만 쓴다. 표는 눈으로 검산되고 감사 때
> 설명하기 쉽지만, 수식은 읽는 사람마다 해석이 갈릴 수 있다.

---

## 1. 누적 — 표 값이 그대로 누적 배수

규정에 "근속 10년 12개월분, 20년 26개월분" 처럼 **도달 시점의 총 지급월수** 가
적혀 있는 경우다.

`지급률` 시트

| 근속연수 | 정규직 |
|---|---|
| 1 | 1.0 |
| 10 | 12.0 |
| 20 | 26.0 |

`지급률규정` 시트

| 규정명 | 방식 | 수식 |
|---|---|---|
| 정규직 | 누적 | |

조회는 **계단식** 이다. 근속 9년은 아직 10년 행에 닿지 않았으므로 1년 행의 값
(1.0)을 쓴다. 중간 구간을 비워 두면 그 구간 전체가 직전 값으로 평평해지므로,
구간을 촘촘히 적거나 누진 방식을 쓰는 편이 낫다.

## 2. 누진 — 표 값이 구간별 연 배수 (권장)

"5년까지는 연 1개월분, 5~10년은 연 1.5개월분, 10년 초과는 연 2개월분" 같은
누진제다. 국내 퇴직금 규정에서 가장 흔하다.

`지급률` 시트

| 근속연수 | 정규직 |
|---|---|
| 0 | 1.0 |
| 5 | 1.5 |
| 10 | 2.0 |

`지급률규정` 시트

| 규정명 | 방식 | 수식 |
|---|---|---|
| 정규직 | 누진 | |

근속 12년이면

```
5년 × 1.0  +  5년 × 1.5  +  2년 × 2.0  =  16.5
```

**첫 행의 근속연수를 0 으로 두는 것을 잊지 마세요.** 1 로 적으면 첫 1년이 계산에서
빠진다.

누진 방식은 근속이 소수로 나오는 중간 시점(예: 5.5년)도 구간 안에서 비례 배분하므로
투영 계산과 잘 맞는다.

## 3. 수식 — 조건부 규정

표로 담기 어려운 것만 여기로 온다. 예를 들어

- 정년까지 3년 미만이면 배수를 깎는다
- 제도구분이 DB 인 사람만 가산한다
- 배수에 상한을 둔다

`지급률규정` 시트의 `수식` 열에 **엑셀 문법 그대로** 적는다.

| 규정명 | 방식 | 수식 |
|---|---|---|
| 임원 | 수식 | `=IF(N-x < 3, t*0.5, t*1.5)` |

### 쓸 수 있는 변수

| 변수 | 뜻 |
|---|---|
| `t` | 근속연수 (중간정산 반영, 소수 가능) |
| `x` | 연령 |
| `N` | 정년연령 |
| `S` | 30일 평균임금 |
| `제도` | `"DB"` / `"DC"` / `"퇴직금제도"` |
| `직군` | 변환 직군명 |

`x` 와 `t` 는 **퇴직 시점** 기준으로 들어온다. 산출기준일 값이 아니다. 정년 임박자
감액 같은 규정이 실제 퇴직 시점을 보고 판단해야 하기 때문이다.

### 쓸 수 있는 함수

```
IF  AND  OR  NOT  MIN  MAX  ABS
ROUND  ROUNDDOWN  ROUNDUP  FLOOR  CEILING  TRUNC
```

`ROUND` 는 엑셀과 같은 사사오입이다(파이썬 기본 반올림과 다르다).

### 예시

```excel
=IF(t < 10, t * 1.0, 10 + (t - 10) * 2.0)   누진제를 수식으로
=MIN(t * 1.5, 45)                            배수 상한 45
=IF(제도 = "DB", t * 1.5, t)                 제도별 차등
=IF(AND(t >= 20, x >= 55), t * 2, t * 1.5)   장기근속 + 고연령 가산
=IF(N - x < 3, t * 0.5, t)                   정년 3년 미만 감액
=ROUND(t * 1.234, 2)                         소수 둘째 자리 반올림
```

### 문법 메모

- 앞의 `=` 는 있어도 없어도 된다
- 같음은 `=` 하나, 다름은 `<>` (엑셀과 같다)
- 거듭제곱은 `^`
- 문자열은 큰따옴표 `"DB"`

## 왜 종전 규칙 코드를 입력란으로 두지 않았나

처음 검토한 안 중 하나가 "종전 규칙 코드를 그대로 붙여 넣게 하자" 였다. 쓰지 않은
이유는 세 가지다.

**1. 실행할 수단이 없다.** 이 프로그램은 엑셀 없이 도는 실행 파일이다. 종전 규칙
런타임이 아예 없으므로 코드를 받아도 돌릴 방법이 없다. 엑셀을 띄워 실행하게 만들면
엑셀 설치·매크로 보안 설정·버전 차이가 전부 산출 전제 조건이 된다.

**2. 파일 하나로 PC 를 장악할 수 있다.** 기초율 파일은 담당자 → 계리법인 → 감사인
사이를 메일로 오간다. 그 파일에 적힌 코드를 그대로 실행한다는 것은, 파일을 건드릴
수 있는 누구나 실행 PC 에서 임의 명령을 돌릴 수 있다는 뜻이다. 파이썬 `eval` 을
쓰는 방식도 같은 이유로 배제했다.

**3. 감사 때 설명할 수 없다.** "이 채무 금액이 왜 이 값인가" 에 답하려면 규정이
**선언적** 이어야 한다. 임의 코드는 전역 상태를 바꾸거나, 실행 순서에 따라 결과가
달라지거나, 무한 루프에 빠질 수 있다. 재현성을 보장할 수 없는 산출은 근거자료가
되지 못한다.

그래서 **부작용이 없는 계산식만** 받는다. 변수 할당·반복문·속성 접근·함수 정의·
임포트는 문법 단계에서 거부된다. 입력한 즉시 검증되므로, 잘못된 수식이 산출
단계까지 흘러가지 않는다.

실무적으로도 엑셀 문법 쪽이 낫다. 계리 담당자가 이미 쓰는 문법이고, 같은 식을
엑셀 시트에 붙여 넣어 검산할 수 있다.

### 자원 한도

외부에서 받은 파일이 산출을 멈추게 할 수 없도록 두 가지 한도를 둔다.

- 거듭제곱 지수는 ±64 까지. 정수 거듭제곱은 임의 정밀도라 `t^99999999` 같은 식이
  메모리와 시간을 모두 삼킨다.
- 수식 하나의 구문 요소는 500 개까지.

## 입력 화면

`산출 가정 입력` 화면(GUI 의 버튼 또는 `pension assumptions`)의 **지급률 규정**
탭에서 방식과 수식을 넣을 수 있다.

- 수식을 치는 즉시 `✓ 확인됨` / `✕ 오류` 가 표시된다
- **수식 미리보기** 버튼으로 근속 1~30년 배수를 표로 확인할 수 있다
- 방식이 `수식` 이 아니면 수식 칸이 잠긴다

## 자주 나는 실수

| 증상 | 원인 |
|---|---|
| 채무가 예상보다 훨씬 작다 | 누진표 첫 행을 `1` 로 적었다. `0` 이어야 한다 |
| 배수가 계단처럼 튄다 | 누진 규정을 `누적` 방식으로 두었다 |
| `규정명을 찾을 수 없습니다` | `지급률` 시트 열 머리글과 명부 `Input` 시트의 변환 직군명이 다르다 |
| 수식이 무시된다 | 방식이 `수식` 이 아니다 |
| `#NAME?` 가 보인다 | 엑셀에서 수식 셀로 입력했다. 앞의 `=` 를 빼고 텍스트로 적는다 |
