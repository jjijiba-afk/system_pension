# 개선된 VBA 모듈

기존 `.xlsm` 의 `Module1` / `Module2` 를 대체하는 모듈입니다. 엑셀 안에서 명부만
정리하고 싶을 때 씁니다. 계리 산출까지 필요하면 EXE 쪽을 쓰십시오.

| 파일 | 내용 |
|---|---|
| `modPensionCore.bas` | 날짜 파싱·연령·정년연령·코드값 정규화·오류 수집 |
| `modUploadList.bas` | `UPLOADLIST_JAE` / `UPLOADLIST_TOI` |

## 가져오기

1. 엑셀에서 명부 통합문서 열기
2. `Alt + F11` (Visual Basic 편집기)
3. 도구 → VBAProject 속성 → 보호 탭에서 잠금이 걸려 있으면 암호 입력
4. **파일 → 파일 가져오기(M)** 로 `modPensionCore.bas`, `modUploadList.bas` 두 개를 가져오기
5. 기존 `Module1`, `Module2` 는 오른쪽 클릭 → 제거 (내보내기 여부를 묻거든
   백업 삼아 내보내 두십시오)
6. `Alt + F8` → `UPLOADLIST_JAE` 실행

`Microsoft Scripting Runtime` 참조는 필요 없습니다 (`CreateObject` 로 늦은 바인딩).

## 원본 대비 달라진 점

### 1. 속도

셀을 하나씩 읽고 쓰던 것을 배열 일괄 처리로 바꿨습니다.

```vb
' 원본: 1인당 30여 회 × 인원수
c_sabeon(jc) = Cells(jc1, 3).Value
c_nm(jc) = Cells(jc1, 6).Value
...

' 개선: 통틀어 2회
src = ws.Range(ws.Cells(26, 1), ws.Cells(lastRow, 36)).Value   ' 읽기
wsOut.Range(...).Value = out                                    ' 쓰기
```

1,000명 기준 셀 접근이 약 5만 회에서 2회로 줄어 수십 배 빨라집니다.

### 2. 메모리

원본은 `Dim c_sabeon(1 To 100000) As String` 같은 정적 배열을 항목마다 선언해
모듈당 30MB 가까이 잡았습니다. 명부가 10명이어도 마찬가지입니다.
개선판은 읽어 들인 크기만큼만 씁니다.

### 3. 오류를 모아서 한 번에

원본은 오류 하나마다 `MsgBox` → `GoTo END_SANCHUL` 로 산출을 끝냈습니다.
오류가 20건이면 고치고 다시 돌리기를 20번 해야 했고, 메시지도 `"3 번째 임직원 …"`
이라 시트에서 직접 세어 찾아야 했습니다.

개선판은 전부 모아 **`검증결과` 시트** 에 남깁니다.

```
재직자명부!K28  사번=A003  (3번째)  30일 평균임금이 체크금액(1,000,000) 미만입니다
```

시트·열·행이 나오므로 엑셀에서 바로 그 칸으로 갈 수 있습니다.

### 4. 날짜 판정 중복 제거

원본은 같은 `Select Case Len(datetr)` 블록을 항목마다 복사해 두었습니다
(생년월일·입사일·중간정산일·전입일·추가지급기준일·퇴사일·사외자산지급일,
두 모듈 합쳐 9회, 900줄 이상). 그래서 한 곳을 고치면 나머지 여덟 곳이 어긋납니다.

`ParseRosterDate` 함수 하나로 모았습니다. 지원 형식은 원본과 같습니다.

### 5. 고친 버그

**길이 8 `yy.mm.d일` 형식의 일자 위치**

`"25.12.3일"` 에서 일자는 7번째 문자입니다. 원본은 블록마다 읽는 자리가 달랐습니다.

| 항목 | 원본 | 결과 |
|---|---|---|
| 입사일 (`Module1` 659행) | `Mid(datetr, 7, 1)` | 정상 |
| 생년월일 (433행) | `Mid(datetr, 6, 1)` | `.` 을 읽어 항상 실패 |
| 중간정산일 (883행) | `Mid(datetr, 6, 1)` | 항상 실패 |
| 전입일·추가지급기준일 | `Mid(datetr, 6, 1)` | 항상 실패 |

**명부 끝 판정**

```vb
c_tot_n = Application.WorksheetFunction.CountA(Range("h26:h100000"))
For jc = 1 To c_tot_n
```

`CountA` 는 값이 든 칸의 **개수** 이지 마지막 행 번호가 아닙니다. 생년월일이 빈
행이 중간에 하나 있으면 명부 끝이 한 줄 잘리고, 마지막 사람이 **오류 없이 조용히**
빠집니다. 100명 중 3명이 생년월일 미기재면 뒤 3명이 사라집니다.
`Input` 시트의 직군 규칙(`CountA(C12:C26)`)도 같은 문제가 있었습니다.

→ `LastDataRow` 가 여러 열을 함께 보고 실제 마지막 행을 찾습니다.

**직군명 공백**

원본은 완전일치 비교라 앞뒤 공백 하나로 "직군을 확인해주세요" 가 났습니다.
→ `Trim` 후 비교합니다.

**사번 중복 검사**

원본은 이중 루프(O(n²))로 비교한 뒤 첫 중복에서 멈췄습니다. 5,000명이면
약 1,250만 회 비교입니다. → `Dictionary` 로 한 번만 훑고, 중복을 모두 보고합니다.

## 그대로 둔 것

원본 산출값과 어긋나면 안 되므로 의도적으로 보존했습니다.

* 두 자리 연도 피벗 (`yy <= 기준일 뒤 두 자리` → 2000년대)
* 만 연령의 `dd >= dd2` 규칙 (생일 당일에 나이가 오름)
* 정년연령 결정 순서 (임금피크 → 정년 초과 → 규정 정년)
* 임직원·성별·퇴직사유 코드값 매핑, 판정 실패 시 기본값
* 중간정산일 공란 → 입사일, 일 기본급 0 → 평균임금/30
* 사번 공란 → 성별+생년월일+성명
* 입사일 > 기준일, 퇴사일 > 기준일 인 사람은 업로드 명부에서 제외

`'임금피크제도에 따른 중간정산'` 의 지급사유 분류는 VBA(4:정년)와 시트 수식
(3:DC전환)이 어긋납니다. 원본을 따라 4로 두었으니 회사 규정을 확인하십시오.
자세한 내용은 [`../docs/vba-mapping.md`](../docs/vba-mapping.md) 를 보십시오.
